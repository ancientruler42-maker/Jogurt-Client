# Jogurt Client

Run: `npm install` then `npm start`. Build the Windows exe: double-click `build.bat` (or `npm run dist`). It outputs
`dist/JogurtClient.exe` (portable, auto-updating) and `dist/JogurtClient-Setup.exe` (installer).
No Windows PC handy? Push the project to GitHub and run the "Build Windows exe" workflow (Actions tab). The exe is attached to the run;
pushing a tag like `v2.1.0` also attaches it to a Release.

## Who can change server settings
Only the Microsoft account `1rth` sees (and can change) Update source and Community server in Settings. Everyone else uses the values in `config.json`, so put your final `apiUrl` and `updateRepo` there before building.

## Auto-update
1. Create a GitHub repo for the client (public).
2. Put `owner/repo` in `config.json` (`updateRepo`) before building, or type it in Settings > Update source.
3. To ship an update: raise `version` in package.json, run `npm run dist`, then create a GitHub Release whose
   tag is that version (for example `v2.1.0`) and attach `JogurtClient.exe`.
4. Clients check at startup. With Auto-update on, they download the new exe, swap it in and restart.

## Community profiles
Host `server/` (see server/README.md), then put its URL in `config.json` (`apiUrl`) or Settings > Community server.
Signing in creates the player's profile automatically. Players choose what is public in the Profile tab.


## Modpack editor, imports and local mod scanning (2.2.0)
- Use **Edit mods** from a modpack's menu to open its editable mod list.
- Import a Modrinth `.mrpack` from the Play page with **Import .mrpack**. Imported Fabric packs are stored locally and installed into their own profile folder.
- In Addons > Mods, add Modrinth projects or drag `.jar` files into the drop area. Local JARs are stored separately from the game directory and copied into place on launch.
- The local safety scanner checks filenames, JAR archive entries and common metadata/text files for known cheat indicators. High-risk matches are blocked; medium/review findings are shown.
- This is a heuristic safety filter, not AI malware analysis or a guarantee that a mod is safe or cheat-free. Unknown, obfuscated or modified mods can evade it. A multiplayer server must enforce its own rules server-side.

## Offline play
After a modpack has been launched once, its files stay on disk. It starts without internet (singleplayer, offline account).
Use "Repair / re-download" in a modpack's menu to force a fresh install.


## Discord Rich Presence ("Show on Discord")
Settings > **Show on Discord** (on by default) shows what you are doing on your Discord profile: "In the launcher",
"Getting <modpack> ready", and "Playing <modpack>" with the Minecraft version, Singleplayer/Multiplayer and a play timer.
Server addresses are never shown.

One-time setup, because Discord needs an application to attach the status to:
1. Go to https://discord.com/developers/applications, create an application and name it **Jogurt Client** (this name is what people see).
2. Copy its **Application ID** into `config.json` as `discordClientId` (before building).
3. In that application open **Rich Presence > Art Assets** and upload `assets/icon.png` with the asset name `jogurt`.
4. Users need Discord > Settings > Activity Privacy > "Share my activity" on.
The setting shows a status line (Connected / Discord not running / no app ID) so problems are easy to see.

## Jogurt in-game theme
Settings > **Jogurt in-game theme** (on by default). Every time you press Play the launcher writes a resource pack
(`JogurtUI.zip`) into the modpack's `resourcepacks` folder and turns it on in `options.txt`, above vanilla and below any
pack you picked yourself. It gives Minecraft green glass buttons and sliders, a green hotbar, green menu backgrounds, an
aurora title-screen panorama and the Jogurt cup + wordmark in place of the Minecraft logo. Turn the setting off and the
pack is removed again on the next launch.
The textures are generated by `tools/make_ingame_pack.py` (Python 3 with Pillow, NumPy, SciPy). Edit it and run
`python3 tools/make_ingame_pack.py` to restyle everything. The right textures are picked per Minecraft version:
1.20.2+ uses GUI sprites, older versions use `widgets.png`; 1.20+ uses the single-row title logo, older ones the split logo.
Inventory/crafting screens are not re-textured.

## Updates (no reinstall needed)

1. Put releases on GitHub as **owner/repo** with a version tag (`v2.2.2`) and a `JogurtClient.exe` (or portable) asset.
2. Set `"updateRepo": "owner/repo"` in `config.json` (or in Settings if you are the owner account).
3. Users with **Auto-update** on get the new build on next launch; otherwise a banner appears: **Update now**.

The app replaces its own `.exe` and restarts — no manual Setup run required for normal updates.
